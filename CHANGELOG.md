## 2.1.0 — unreleased

Parity with the browser, Flutter and iOS SDKs: the same API names, wire format and replay architecture. The SDK and its Gradle plugin share the version 2.1.0, and the SDK leaves beta.

- Wireframe segments and exception clips use layout placeholders when their serialized inline raster data URLs exceed 128 KiB.
- **Start with a token** (CONTRACT §16): `Traceway.init(application, TracewayOptions(token = "YOUR_TOKEN"))`. `TracewayOptions.baseUrl` names a self-hosted server and defaults to Traceway Cloud, `https://cloud.tracewayapp.com`; `https://` is added when it has no scheme (`http://` for `localhost`, `127.0.0.1`, `10.0.2.2`, `[::1]`) and a trailing `/api` or `/api/report` is dropped. Without a token the SDK runs standalone with `telemetry`. `token` and `baseUrl` are the constructor's first two parameters.
- **Connection strings are deprecated**: `Traceway.init(application, connectionString, options)` still works, for every form the dashboard ever showed (`token@https://host`, `/api`, `/api/report`, trailing slashes, no scheme, whitespace, a server under a sub-path; CONTRACT §16.1), and logs one deprecation warning with the new form. An invalid one logs a warning and leaves the SDK off; it never throws.
- **Nothing calls `/api/report` any more**: `TracewayOptions.legacyConnectionString` and the 1.x report drain are removed. The SDK recovers the newest 20 reports a beta SDK associated with the same server and token, up to 12 hours old. Recovered issues carry `traceway.previous_run = true`. A successful handoff acknowledges the source file. Unscoped 1.x files have no project identity and are discarded.
- **Java**: `TracewayOptions.builder()` and `toBuilder()`, with one setter per option (a null value means the default; `ignoreErrors(List<?>)`, `propagateTraceHeaderUrlPatterns(Pattern...)`), and `TracewayTelemetry.builder()`. A Java `null` for any option, through a builder or a constructor, means its default instead of a `NullPointerException` before `Traceway.init` (the options' object parameters are nullable now: `version`, `attributes`, `replayImages`, `metricDimensions`, `propagateTraceHeaderUrls`, `propagateTraceHeaderUrlPatterns`, `TracewayTelemetry.headers`, `TracewayTelemetryEndpoint.url` and `headers`). `TracewayInteraction.makeCurrent()` returns a `TracewayScope` (`AutoCloseable`) for try-with-resources; `TracewayClient.startRequest(method, url)` has a Java overload.
- **Compose screens**: `Traceway.trackNavigation(navController)` (import `com.tracewayapp.traceway.navigation.trackNavigation`; Java `TracewayNavigation.track`) reports every destination of a `NavController` with its path and route template (`/orders/8841`, `/orders/:id`), arguments of any type, type-safe routes by their class's simple name, `pop` when the user goes back. `Modifier.tracewayScreen(path, route)` names a screen no controller shows. `navigation-runtime` is a compile-only dependency.
- **`version` defaults to the app's `versionName`** (it was `unknown` unless the app passed `BuildConfig.VERSION_NAME`, which a new AGP 8 project does not have).
- **ProGuard UUID without code**: the Gradle plugin writes the build's UUID to the app's assets (`traceway/proguard-uuid.txt`) and the SDK reads it when `proguardUuid` is not set, so applying the plugin is enough for readable release crashes. `BuildConfig.TRACEWAY_PROGUARD_UUID` is still added when the module builds a `BuildConfig` (AGP no longer warns about it otherwise). A minified build that has no UUID logs one warning.
- **Gradle plugin** (`com.tracewayapp.symbols` 2.1.0): **fix: the logcat rewrite crashed apps on an older SDK** (`NoClassDefFoundError: TracewayLogcat` at the first `Log` call): it now rewrites only when the variant's runtime classpath holds `com.tracewayapp:traceway` 2.1.0 or newer (its prereleases, or the SDK as a project, included), and otherwise warns once per variant and leaves `Log` alone. When the variant's R8 rules strip `android.util.Log` with `-assumenosideeffects`, the same rule is added for `TracewayLogcat`, so the lines stay stripped. `logcat { includeDependencies = false }` rewrites the module's own classes only; `logcat { disabledFor("release") }` leaves variants or build types alone. The plugin may be applied before or after the Android plugin, `traceway.url` defaults to `https://cloud.tracewayapp.com` (a blank value too, so `url = System.getenv("TRACEWAY_URL") ?: ""` works on Cloud) and the upload's log line names the endpoint, and an app whose package is under `com.tracewayapp.traceway` (the example) is rewritten too.
- **Fix: pictures with transparency replayed as black boxes**: a picture with alpha is now always PNG, at most 192 px on its longest side (CONTRACT §14.5 as corrected); it was JPEG above 96 px. One over 48 KiB after the half-size retry is left out.
- **One process**: `Traceway.init` starts the SDK in the app's main process only and returns null in another one (`:sync`, `:remote`), which shared the state directory; option `allProcesses` runs it everywhere, each process with a state directory of its own (`traceway_v2-sync`).
- **`reportHangsInDebug`** (default `false`): hangs count under a debugger too, the `app.hang` metric and `AppHang` issues, as on iOS and Flutter.
- **What a new user is told**: one warning, whatever `debug` says, when the server rejects the project token (HTTP 401/403) or does not accept OTLP (404), and one when a `Traceway` method is called before `Traceway.init`. With `debug`, a line says why an exception or a message was dropped (the `ignoreErrors` pattern that matched, or `beforeCapture`) and that breadcrumbs wait on the device until an error.
- **Fix: `Traceway.init` touched the disk on the main thread** (`noBackupFilesDir` creates its directory), which crashed apps with a `StrictMode` `penaltyDeath` policy in `Application.onCreate`: the state directory is now made by its first write, on the SDK's threads, at the same place.
- **Crash safety**: the logcat bridge and the `Traceway.client` getter read the client inside `guarded`, so even a failure of the client's class initialisation cannot reach the app's `Log` call.
- **Upgrading from 2.0.0-beta.1**: the first 2.1 start counts as a first start for exit reasons (it notes where Android's history ends and reports nothing older).

- **Native crashes and ANRs** (Android 11+): at the next start the SDK reads `ApplicationExitInfo` records newer than the last one seen. `REASON_CRASH_NATIVE` is a `NativeCrash` issue (on Android 12+ with the tombstone's signal, abort message, cause and crashing-thread frames, parsed by a small built-in protobuf reader; else Android's description) and counts in `app.crash`; `REASON_ANR` is an `ApplicationNotResponding` issue with the main thread's stack from the ANR dump, plus an `app.anr` count; `REASON_LOW_MEMORY` counts `app.oom`. They carry the session the dead process was in. Option `captureExitReasons` (default `true`). No native signal handler.
- **App hangs**: the hang watchdog takes the main thread's stack once it has been blocked for `appHangThresholdMs` (default 2000) in the foreground, and reports an `AppHang` issue (`Main thread blocked for 3.2 s`, with the screen) when it ends. A hang the process does not survive is reported at the next start with `app.hang.fatal = true`, unless Android recorded an ANR for that run (the ANR is the issue then). Not under a debugger. Option `captureAppHangs` (default `true`).
- **Logcat**: the `com.tracewayapp.symbols` Gradle plugin rewrites `android.util.Log.v/d/i/w/e/wtf/println` calls in the app and its dependencies (Timber included) to the new `TracewayLogcat`, which calls the real `Log` first and then records a console line with `log.source = "logcat"` and `log.tag`, under the same `signals.console` mode, minimum severity and sample rate. Extension `traceway { logcat { enabled = true; minLevel = "info" } }`; nothing is rewritten when the SDK (2.1.0 or newer) is not on the runtime classpath.
- **`Traceway.tracer`** (Java `Traceway.getTracer()`, also `TracewayClient.tracer`): the SDK's OpenTelemetry tracer for the app's own spans, which carry the session id and are children of the interaction they start in; null before the SDK started and after `shutdown`. The SDK still never registers itself as the global OpenTelemetry. `opentelemetry-api` is now an `api` dependency.
- **`flush()` on the main thread** waits 2 s at most, whatever timeout it is given (an ANR comes at 5 s); off the main thread the timeout (10 s by default) still applies. `shutdown()` flushes the same way.

- **Replay images**: wireframe recordings can carry the pictures image views show (`ImageView` bitmaps, bitmap backgrounds), never a screenshot and never under a mask. The collection setting `replay.images` (`off`, `wifi`, `always`; `wifi` by default) chooses when, `TracewayOptions.replayImages` (`TracewayImagePolicy`, `ALWAYS` by default) caps it, and the lower applies; `wifi` means an unmetered connection, checked when a frame is captured. Pictures are encoded off the main thread as JPEG 0.45 (always PNG, at most 192 px, for ones with alpha) at one pixel per dp, at most 384 px and 48 KiB each (one retry at half size), at most 128 kept (those not shown for 30 s make room, else the one shown longest ago; a new session starts again) and 4 MiB per session, and styled as `.im.p<N>` rules (CONTRACT §14.5: smaller pictures, more of them). The app's bitmap is only read on the main thread, where it is copied at that size; the encoder reads the copy. Session events carry `traceway.replay.images` and `traceway.replay.image_bytes`. Compose images stay placeholders.
- **Keyboard**: while the soft keyboard shows, the replay draws a neutral "Keyboard" box where its IME inset says it is (ids 12–14, light `#d1d3d9` or dark `#2c2c2e`), as the iOS SDK does.
- **Shared stylesheet**: `wireframeCss` is byte for byte the stylesheet the three mobile SDKs share (adds the `.sk` skeleton rules); the screen node names Android's font stack inline.
- **Logs**: `Traceway.log(message, level, attributes)` with `TracewayLogLevel` (`TRACE` to `FATAL`); records carry `log.source = "api"` (`stdout`/`stderr` for printed lines). `recordLog` is deprecated.
- **Interactions**: `Traceway.startInteraction(name, attributes)` returns a `TracewayInteraction` (`traceId`, `spanId`, `run`, `setAttribute`, `captureException`, `end`): a span (`traceway.interaction: true`) that requests made in `run` are children of and that exceptions and logs recorded there point to; a failed one is sent at once.
- **Screens**: `Traceway.setRoute(template)` names the current screen's route template; navigations and issues carry `app.screen.route`, and metrics group by it. Exceptions and messages carry the screen they happened on (`app.screen.name`, `app.screen.route`, `app.screen.previous`, `app.screen.duration_ms`, `viewport`). `Traceway.recordNavigation` takes `from`.
- **Filtering**: options `ignoreErrors` (strings and regexes matched against `Type: message`; null uses `TracewayOptions.DEFAULT_IGNORE_ERRORS`, network noise and 4xx) and `beforeCapture` (`TracewayCapturedError`, return false to drop). **Behaviour change**: `UnknownHostException`, timeouts and similar network errors are no longer reported by default. Crashes are always reported.
- **Privacy masks**: `View.tracewayMask` (a Kotlin property: set a `TracewayMaskMode`, or null to remove it; an `android:tag="traceway-mask"` / `"traceway-blank"` reads back through it) next to `Traceway.mask(view, mode)` / `Traceway.unmask(view)` for Java and `Modifier.tracewayMask(mode)` in Compose. A `traceway-mask` / `traceway-blank` test tag now masks Compose taps too, and is no longer reported as the tapped node's id.
- **`Traceway.currentSessionId`** on the facade.
- **`traceway.collection.health`**: emitted a second after replay segments are refused by the session budget, errors are suppressed by the flood guard or replay uploads are given up, then with a delay doubling up to 5 minutes; the session is updated once. Session events (`session.start`, `traceway.session.update`, `session.end`) carry `traceway.error.suppressed_total` too, as in the iOS and browser SDKs.
- **Wireframe fidelity**: an outlined `MaterialCardView` keeps its outline (the stroke its foreground draws over the card's content).
- **Foreground fixes**: after a cold start the wireframe recorder now goes to the background (the replay shows "App in the background" and capturing stops) when the app's last activity stops; it used to stay in the foreground for the life of the process. When Traceway starts while an activity is already on screen (after a consent screen, or `Traceway.init` again after `Traceway.shutdown`), that activity's stop no longer reports a trip to the background while another activity is showing.
- **End-to-end check**: `tools/e2e/run.py` drives the SDK in a scripted app (`E2EScriptTest`) against a running Traceway and checks what the server holds after each phase.
- **Options order**: `TracewayOptions` parameters follow the order shared with the other SDKs (`token, baseUrl, sampleRate, debug, version, …`); pass them by name, or use the builder from Java.
- **Crash safety** (the SDK never takes the app down): every public method of `Traceway`, `TracewayClient` and `TracewayInteraction` contains the SDK's own failures and takes Java nulls (a null where a value is needed does nothing; parameters Java can pass null to are nullable, the Kotlin calls are unchanged). `Traceway.init` never throws: any failure is logged and it returns null, leaving no hook, thread or crash handler behind; a hook that cannot be installed is skipped and the rest runs. Every hook the SDK installs (activity, frame and draw callbacks, the hang probe, network callbacks, the OkHttp interceptor, image and glyph encoders, its timers) contains its own failures, through one internal helper, `guarded`, which logs one line per place with `debug`. The app's own exceptions still reach it unchanged (an interaction's `run` block, an OkHttp call), and crashes still go to the handler that was there before. Desugaring is still required below API 26; without it, on API 21–23 `Traceway.init` logs and returns null instead of every later call throwing `NoClassDefFoundError`, and on API 24–25 the SDK starts but what it records through OpenTelemetry (which reads the time with `java.time`) is dropped, without reaching the app. `CrashSafetyTest` covers it.
- **Fix: crashes with `persistToDisk = false`** (or without a usable state directory) are reported: sent right away within the 2.5 s crash budget, on any thread, instead of being written to an outbox that cannot keep them and lost.
- **Fix: replay images** could abort the app: the encoder read the app's bitmap on its own thread, which an image loader may recycle meanwhile. The bitmap is now copied on the main thread at its displayed size (at most 8 new copies per frame and 4 MiB waiting; a hardware bitmap through a `Picture`, API 28+) and only the copy is encoded. A hardware bitmap is no longer copied at full size first.
- **Fix: replay images** stopped for the rest of the process after the 64th distinct picture.
- **Fix: OkHttp**: a failure while reading a successful response for its span (a body whose length cannot be read) no longer fails the app's call.
- **Fix**: `getInstanceId()` returned the nil UUID right after `init`; it is null until the SDK has read the id. **API**: `TracewayClient.getInstanceId()` is `String?`, as `Traceway.getInstanceId()` was.
- **Fix**: when Traceway starts while an activity shows, the app counts as in the foreground, so its first trip to the background is seen (buffer and metrics saved, replay segment cut, hang watchdog stopped).
- **Fix**: `shutdown()` gives the uncaught-exception handler back, unregisters its fragment callbacks and stops the wireframe encoder threads; a later `init` follows fragments of activities created before it from their next resume. `flush()` after `shutdown()` returns at once instead of waiting its whole timeout.
- **Fix**: with no uncaught-exception handler set before Traceway, a crash's stack trace is printed as without it.
- **Fix**: a server that answers every OpAMP poll with ReportFullState gets one poll at once, then none faster than the minimum interval (it was a tight loop).
- **Fix**: the ring buffer takes at most a sixteenth of the heap (and 64 MiB) whatever `buffer.maxBytes` the dashboard sets.
- **Fix**: the wireframe recorder no longer keeps the windows of its last capture (and so destroyed activities) alive while it is stopped, nor the Compose capture its last view; the peak-memory read (`/proc/self/status`) left the main thread.
- **Internals**: wireframe files renamed to the shared vocabulary (`WireframeRoots`, `WireframeCapture`, `WireframeComposeCapture`, `WireframeCss`, `WireframeDiff`, `WireframeGlyphs`, `WireframeImages`, `WireframePointer`); `docs/wireframe.md` describes the pipeline.

## 2.0.0-beta.1

Rebuilt on the official OpenTelemetry Java SDK, at parity with the browser SDK 2.x and the Flutter SDK 2.0: OTLP logs, spans and metrics, a ring buffer on the device, remote config over OpAMP, captures, recording triggers, taps, app performance metrics, and wireframe session replay.

- **Breaking**: requires a Traceway server with OTLP/OpAMP support for Android projects; the 1.x `/api/report` protocol is gone. Apps with `minSdk` below 26 must enable core library desugaring. Options `debounceMs`, `retryDelayMs`, `maxPendingExceptions`, `maxLocalFiles`, `localFileMaxAgeHours`, `eventsWindowMs`, `eventsMaxCount` and `capturePixelRatio` were removed, as were the 1.x transport and test methods of `TracewayClient` and the `ReportSender` interface. `Traceway.init` returns `TracewayClient?`: null when the connection string or `telemetry` is invalid, which is logged instead of thrown.
- **OpenTelemetry inside**: logs and spans are records of private `SdkLoggerProvider` / `SdkTracerProvider` instances of `opentelemetry-sdk` 1.68, sent through the official batch processors and encoded with its OTLP marshalers; the app's own OpenTelemetry setup is untouched. Requests go through the SDK's own HTTP sender, gzip-compressed, so no HTTP library is added to the app.
- **Ring buffer**: console lines, HTTP requests, screens, taps and custom events stay on the device (2 MiB / 10 minutes) and are uploaded when an exception or a trigger asks for them. The buffer is saved when the app goes to the background and restored when the same session goes on after a restart.
- **Remote config over OpAMP**: signal modes, sample rates, buffer sizes, triggers and on-demand captures from the dashboard's Data Collection page. Init options are ceilings. The last applied settings are cached for the next start. The OpAMP client is checked byte for byte against `opamp-go` (`scripts/opamp-golden`).
- **Local config**: `TracewayOptions.collection` takes a settings document, under the remote rules or on its own with `remoteConfig = false`.
- **Crashes survive the process**: an uncaught exception, the breadcrumbs its trigger flushes and its replay clip are written to disk before the previous handler runs, then, off the main thread, sent within a budget of 2.5 seconds; a main-thread crash and whatever is left go at the next start. Failed batches wait in an on-disk outbox (200 batches, 20 MiB, 24 h).
- **Wireframe session replay** (`screenCapture = true`): the view tree of every app window (activities, dialogs, popups) and Jetpack Compose semantics recorded as rrweb HTML snapshots and mutations, replayed by the dashboard's rrweb player. Captured only after frames that drew, at most `fps` (10) a second; unchanged views are reused between frames; a view whose own code throws while it is read costs its own nodes, not the frame; a window that just opened joins from the next frame, once it is in its place (a Compose menu is first added at the corner of the screen). Material components keep their shapes and colors, and a `TextInputLayout`'s label floats over its field. Small vector icons are drawn as their shape, one picture per shape whatever its tint. Text fields are masked unless `replay.maskAllInputs` is off, password fields always. `Traceway.mask(view, mode)`, `android:tag="traceway-mask"` / `"traceway-blank"` and `Modifier.tracewayMask()` mask a subtree.
- **Recording triggers** (`click`, `hover`, `navigation` and `log` steps) run on Android with the browser SDK's sequence engine. Taps are recorded as `browser.user_action.click` with a CSS-like selector of the view (`MaterialButton#pay`).
- **Screens**: activities and AndroidX fragments are reported automatically as `/ClassName`; `Traceway.recordNavigation` reports Compose Navigation or other routers.
- **App performance metrics**: cold, warm and hot start, time to initial and full display per screen (`Traceway.reportFullyDisplayed()`), slow and frozen frames (`FrameMetrics`), hangs, crashes, sessions, daily users and affected users, peak memory and HTTP requests by host, aggregated on the device as base-2 exponential histograms and counters and uploaded to `/api/otel/v1/metrics`. App-defined metrics with `Traceway.metric` / `Traceway.count` and dimensions with `metricDimensions` / `Traceway.setMetricDimension`.
- **Network**: `TracewayOkHttpInterceptor` records OkHttp calls as client spans; `startRequest` / `endRequest` record any other HTTP stack. `propagateTraceHeaderUrls` / `propagateTraceHeaderUrlPatterns` add a W3C `traceparent` header.
- **Other OpenTelemetry backends**: `TracewayOptions.telemetry` sends logs, spans and metrics to any OTLP/HTTP receiver, next to Traceway or standalone (no connection string).
- **1.x migration**: `legacyConnectionString` delivers reports a 1.x build left on the device to its project's `/api/report`.
- New API: `Traceway.track`, `setAttribute(s)`, `removeAttribute`, `clearAttributes`, `recordNavigation`, `recordLog`, `reportFullyDisplayed`, `metric`, `count`, `setMetricDimension`, `mask` / `unmask`, `refreshConfig`, `shutdown`, `getInstanceId`.
- Build: Android Gradle Plugin 8.7, Kotlin 2.0, compileSdk 35.
